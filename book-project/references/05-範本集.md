# 05 範本集

可直接複製、改書名就能用的模板。開新專案、開新章、開新台帳時從這裡拿。

## 一、`AGENTS.md` 骨架

```markdown
# <書名>（專案藍圖）

> 本檔為跨 Agent 通用的專案藍圖（AGENTS.md 開放標準）。任何 Agent 的每個 session 都應先讀本檔＋`handoff.md`。

## 專案簡介
<一句話：這本書是什麼、要完成什麼>

## 關鍵時程
<!-- 格式：- 事件名稱：日期（說明）；沒有就留白 -->
（留白，之後補）

## 目標與路線圖
<!-- 用 checklist 追蹤，收工技能會更新這裡 -->
- [ ] 階段一：企劃與定位（作者訪談、出書企劃、章節企劃卡）
- [ ] 階段二：書稿撰寫與統稿
- [ ] 階段三：視覺與工具資產
- [ ] 階段四：讀者驗證
- [ ] 階段五：出版

## 資料夾結構
<!-- 初始化時自動掃描生成，之後新增檔案要更新 -->
（貼上 tree）

## 同步層級
| 層級 | 平台 | 位置 | 讀取時機 |
|------|------|------|---------|
| L1 | 本地 | `AGENTS.md`＋`handoff.md` | 每個 session |
| L2 | GitHub | <owner>/<repo>（私有） | 指定時 |
| L3 | 筆記 | `專案工作流程.md` | 有需要時 |

## 工作約定
- 開工先讀 `handoff.md`，收工必更新 `handoff.md`
- 修改共用檔案前先讀最新內容，避免覆蓋其他 Agent 的變更
- 所有回應與文件使用繁體中文
- 修改前先確認計畫，優先保留原有資料結構

## 安全與隱私（不可違反）
- 不把 API key、密碼、憑證寫進 repo，也不要貼進 `AGENTS.md`／`handoff.md`
- 錄音、照片、逐字稿、可辨識個資不進 repo
- 要公開分享前，先確認檔案裡沒有上述內容
```

## 二、`handoff.md` 骨架（只放交接必需資訊，一頁讀完）

```markdown
# 交接檔（handoff.md）

> 任何 Agent、任何電腦接手前必讀；收工時必更新。詳細脈絡放 `專案工作流程.md`。

## ⏯️ 目前做到哪
<日期> 完成：<1.–5. 條列，每條寫「做了什麼＋commit 編號/是否已推」>

## 🚦 目前狀態
- 書稿：<各章狀態、最新定稿>
- 素材／授權：<哪些已取得、哪些待補>
- 驗證／網站：<是否上線、資料庫是哪一個>
- 本地 git：<是否同步、有無未 commit 變動>
- 其他進行中：<…>

## ➡️ 下一步
1. <具體、可執行的 1–3 項（不要寫「繼續寫作」這種模糊項）>

## ⚠️ 注意事項
- <本次新踩的坑、暫時 workaround、環境限制>

## 🕐 最後更新
- 時間：YYYY-MM-DD HH:MM（收工）
- 更新者：<Agent> @ <電腦名>
- Git push：✅ 已推（<commit>）／❌ 未推（原因）
```

## 三、章節企劃卡

```markdown
### 第 N 章｜<章名>

| 欄位 | 內容 |
|---|---|
| 章節任務 | 這一章替讀者解決什麼（一句話） |
| 開場故事 | 場景＋來源（作者經驗／授權案例／明確標示的綜合示例） |
| 核心觀點 | 讀者要帶走的那一句 |
| 內容範圍 | 寫什麼／**明確不寫什麼** |
| 案例或代表素材 | 素材編號（或「待補」） |
| 一項主要工具 | 表格／清單／腳本／檢核表（只放一個） |
| 今晚就能做 | 具體到今晚可完成的動作 |
| 待補與審讀 | 缺什麼素材、要找哪一類專業者審讀 |
```

## 四、素材台帳

```markdown
## 編號規則
- `FI` 訪談、`PH` 照片、`AU` 錄音、`DO` 文件、`OB` 物件、`EX` 外部案例

## 素材清單
| 編號 | 來源人物／來源 | 日期與地點 | 可用章節 | 事實狀態 | 授權狀態 | 匿名需求 | 原始檔位置 |
|---|---|---|---|---|---|---|---|
| FI-001 | <關係代碼> | 2026-10-11 取得／2026-10-13 校訂 | 第三、四、八章 | 已確認 | 可匿名引用 | 關係稱呼 | <受控位置代碼> |

## 章節資料缺口對照
| 篇章 | 優先補訪／素材 | 狀態 |
|---|---|---|
| 第五章 | 容易引起反感的邀請語；成功邀回家人的案例 | 部分補入（每月一次家聚餐會）；邀請語案例待補 |
| 第六章 | 異地家庭參與案例；錄影與隱私界線 | 作者家族無此經驗；如需案例須另尋其他家庭並取得授權 |
```

狀態用語建議：`待補`／`部分補入（<補了什麼>）`／`作者確認無此經驗`／`已完成`。

## 五、檔首「初稿說明」三種寫法

```markdown
<!-- 作者真實經驗為主 -->
> 初稿說明：本章以作者真實經驗為主，事實已經本人確認。

<!-- 示例 -->
> 初稿說明：依章節企劃撰寫，開場為常見家庭情境，並非作者家族的特定事件；作者已確認內容方向。

<!-- 混合（有示例也有真實段落） -->
> 初稿說明：開場為綜合示例，不影射特定成員；「〇〇」一節已補入作者家族的真實做法（經本人校訂並同意匿名使用）。
```

## 六、訪談開場白與停止訊號

```markdown
> 今天我們想談 <主題>，大約 <時間>。我會錄音，只供整理 <用途>。
> 你可以不回答任何問題，也可以隨時叫停。整理成文字後會先給你看，未經你同意不公開。
> 開始之前想確認三件事：今天有哪些主題不要談？可以用什麼方式示意暫停？這份內容最多可以分享給誰？
```

停止訊號（訪談前約定，受訪者使用後不得被追問或責怪）：
- 直接說「先停一下」或「這段不要記」
- 用手勢示意暫停錄音
- 把某個題目標成「以後再談」
- 要求刪除剛才的一段錄音或文字
- 結束整場訪談，不必說明理由

## 九、意見調查題目骨架（6 區段、約 8–12 分鐘）

1. **基本資料**：年齡區間、居住距離、目前與家人互動頻率（→ 推導畫像）。
2. **真實經驗**：最近一次 <主題> 是什麼情況（誰發起、幾個人、遇到什麼困難）。
3. **困難與現況**：你遇過的困難、你現在怎麼處理、試過什麼方法。
4. **觸發點與購買情境**：什麼情況會讓你主動找資料／買書／用工具。
5. **內容期待**：看完概念後，你覺得與你的需要有多接近；想先看到哪一章。
6. **承諾與分流**：願意試讀嗎？願意試用工具嗎？可否接受後續訪談（另約）。

選填題務必標示；跳題邏輯要測過；開放題保留 2–3 題。

```
- 第五章：新增「每月一次家聚餐會」真實做法（置於「相聚寧可小而完整」一節）

- 第六章：作者確認家族無此經驗，正文維持示例；初稿說明與查核清單註明「須另尋其他家庭」
- 素材台帳：FI-001 對應章節加第八；第五、六、八章缺口狀態更新
```
